Минимальный gate: реальный workflow с ошибками и ограничениями, уникальные screenshots/пример, проверка Q-ID и версии, уникальные title/H1/description, self-canonical, внутренние ссылки, корректный mobile layout, подтверждённая форма заявки. После одной страницы смотреть index status и qualified enquiries, не обещать рост трафика в заданный срок.

Search Console, аналитика и запуск

  1. Код WMS. Указанный путь содержит только лендинг и UI prototype. Предоставить путь к backend, миграциям, runtime, RF и voice. Для каждого Q-ID сохранить commit, code path, сценарий, результат и границы. До этого новая главная — консервативный кандидат на review.
  2. Search Console: использовать существующий ресурс. Войти в нужный Google account; выбрать quark.build Domain property (или существующий https://quark.build/ URL-prefix). Settings → Ownership verification: проверить действующий способ и не удалять DNS TXT. Если URL-prefix уже verified, не создавать его повторно и не выдумывать verification token.
  3. До deployment. В существующей GSC проверить / и /screens.html: index status, последний crawl, user-declared и Google-selected canonical; Pages: noindex/duplicates/404; Sitemaps: результат текущего sitemap; Performance за доступный период: queries/pages/countries/devices. CWV зафиксировать только при наличии данных. Данные в этом аудите не извлечены, статусы не выдуманы.
  4. Vercel preview. Развернуть ветку в том же Vercel проекте. Проверить runtime Node с fetch/AbortSignal, /vision → 200, /vision.html → 308 /vision, /index.html → 308 /, /webrf → noindex, неизвестный URL → 404. Канонические ссылки на preview всё равно указывают на production domain. Preview не добавлять в sitemap/GSC.
  5. Форма. Согласованную тестовую заявку отправить на preview и проверить её в Formspree и почтовом ящике владельца. Mock tests не доказывают реальную доставку. Проверить, что существующий Formspree form принимает server-to-server запросы, активен и не требует дополнительной настройки. В случае 502 UI предлагает retry/email, success не показывается. API logs не выводят upstream body. Включить доступные Vercel WAF/rate limits при реальном злоупотреблении; origin check/honeypot не заменяют anti-spam.
  6. Production. После проверки возможностей и формы — merge в production branch. Проверить адреса, canonical в HTML и реальную страницу /vision. Только после фактического deployment считать SEO-настройки активными.
  7. Sitemap. В существующем GSC Sitemaps отправить https://quark.build/sitemap.xml или проверить уже отправленный адрес. Дождаться результата Success и проверить discovered URLs. Для / и /vision выполнить Live URL inspection и при необходимости Request indexing. Это не гарантирует индексацию.
  8. DNS. Добавить www в текущий Vercel проект и настроить DNS по его данным, затем проверить 308 на https://quark.build/ с сохранением path/query. Не менять работающий apex или GSC verification TXT без необходимости.
  9. Аналитика. Vercel → проект → Logs → production → filter quark_leads. Считать lead_submit, lead_success, lead_error; success/submit — доля принятых провайдером отправок. Фильтр source=google, medium=organic — грубая атрибуция Google-поиска. CTA/form_start — счётчики событий, а не уникальные посетители. Нет pageview/session denominator, cross-page attribution, campaign tracking или постоянной БД. Retention зависит от плана Vercel; до истечения срока выгружать счётчики. Удостовериться в доступе и сроке хранения logs. Если нужен постоянный dashboard, выбрать счётчик отдельно; GA4 не создан и не подключён.
  10. Первые страницы. Выбрать язык/рынок после данных GSC, затем выпустить одну страницу №1 и оценить crawl/index/clicks/qualified enquiries. Вторую — после проверки качества, не по расписанию. Пока подготовлен только план: массовых SEO URL и текстовых дублей нет.

Проверка ownership и работа существующего ресурса: Google Search Console — verification, порядок работы с Search Console. Sitemap submission — сигнал, а не гарантия crawl/index.

Проверки подготовленного изменения

  • Синтаксис JS; тесты success/provider error/timeout, consent/email/size/origin/method/honeypot, без PII в аналитике, JS-free redirect, запрет client lead_success.
  • HTML/canonical/sitemap, локальные ссылки и якоря, валидность SVG; desktop/mobile и gallery viewer проверяются в preview.
  • Реальная отправка Formspree и Vercel routing требуют deployment; статический preview и mocked tests их не заменяют.
